Mission Planning

Simulate Glider Position in Westport

Simulating a glider mission / location so glider thinks it is at Westport

  1. Start glider by putting the Green plug in, ProComm open on computer, Freewave on
    2. CTRL C
    3. Put c_air_pump 0
    4. Callback 30
    5. Lab_mode on
    6. Dir config (should have file simul.not)
    7. Cd config
    8. Copy simul.not simul.sim
    9. Exit reset (reboot to go into simulation mode, will complain about attitude)
    10. CTRL C
    11. Put c_air_pump 0
    12. Callback 30
    13. Lab_mode on (glider will now be in simulation mode)
  2. Go to SFMC0 website
    1. Select WA551 (or current glider deployment name) under Deployments
  3. Archive previous deployment (if this has not been done already, it may have also been ‘Recovered’ in which case it will be under Recovered instead of Archived)
    1. Options - > Archive Deployment
  4. Mission Control -> Glider terminal -> (select glider of choice)
    1. Remove active script (under ’Script)
  5. Load mission
    1. Cd missions
    2. Dir
    3. Loadmission ldsimwa.mi (loading Anatoli’s simulated position)

      1. Loadmission will load sensor parameters but not behaviors ex. Loadmision watercl.mi

        sensor: m_water_vx(m/s) 0

        sensor: m_water_vy(m/s) 0

  6. Bring glider outside
    1. Callback 0 0 (call immediately, primary #)
  7. In SFMC, once Iridium connects you should see something in the ‘Active Terminal’. Once SFMC ‘sees’ the glider, you can disconnect for Iridium
  8. Delete simul.sim file
    1. Navigate to config directory
      1. Del simul.sim
      2. Dir (confirm deletion)
      3. Cd.. (go up one directory)
      4. Exit reset (make sure to callback 30 so it doesn’t pick up location)
      5. Bring glider inside
  9. Glider should now appear like it is in the water near Westport
  10. While connected via Freewave, download important files from glider
    1. From Terminal
      1. Zs autoexec.mi (in config dir)
      2. Zs longterm.sta (in state dir)
      3. Zs proglets.dat (conci to go to SciDOS, quit to return to GliderLAB)
      4. You must be in each folder for this to work
    2. Drop three downloaded files to glider
      1. Options -> view glider details -> config file drop zone
  11. Test science sensors
    1. Put c_science_all_on 0
    2. Put c_science_send_all 1
    3. Get sci_”sensor name” (for science sensor readout, ex. Get sci_water_temp)
  12. Exit glider
    1. Exit reset
    2. CTRL C
    3. Put c_air_pump 0
    4. Callback 30
    5. Get m_vacuum
    6. Get m_battery
    7. Exit
    8. Pull Green plug

Configure project in SFMC

  1. Configure project assignment
    1. Options -> configure project assignment -> WA551(or WA_VEMCO if using SL592) -> save
    2. -> Access Mission plan -> nhg2test (or vemco_azfp if using SL592)
  2. Configure waypoints
    1. Configuration -> Mission Planning -> Waypoints Plan
    2. Clone WA_Sept2021 to different name associated with this deployment (ex WA_2024_may)
    3. Group -> OSU
    4. Release Waypoint Plan
    5. Options -> Access Mission Plans -> Modify Selected Mission Plan -> Modify Waypoints Plan -> WA_sept2024 (or whatever the copied name is that you just created)
    6. For the beginning of the deployment, use a 15m surface plan (15surface_plus_wpt)(always use wpt)
      1. This is so it surfaces after a 15 minute test dive, this will change to 1hr and then 2hr as you traverse north to the first waypoint.
    7. Release plan -> process
    8. The file number you choose is based on what is being called in the mission plan (aka nhg2test or vemco_azfp etc)
      1. Double check the number being used by going to the mission plan when proceeding files (10,20,30,40 etc), located in autoexec.mi file
      2. Need to figure out how to check this
    9. File number = 60 -> generate
    10. Delete all files except files that were modified
      1. Keep goto_l40.ma - modified waypoints
      2. Keep surfac41.ma - surfacing interval
    11. Add yo40.ma file (thruster on file) to to-glider drop zone in glider terminal
      1. In the GliderGroup -> slocum -> piloting file there are two thruster ma files
      2. Change the name of the yo40_thruster_on.ma file to yo40.ma
      3. Drop this in the to_glider drop zone in the glider terminal
      4. This will turn on the thruster
      5. To turn off the thruster rename the glider_off file to yo40.ma and put in the to_glider drop zone
    12. Change the script to driftdo.xml after glider dives
    13. Delete to-science files
    14. When glider is running mission, it will automatically grab files from glider file drop, but when not running a mission you need to Ctrl-F to re-read ma files.

Create new maps in SFMC

We store our maps on the CEOAS maps GeoServer https://gliderwms.ceoas.oregonstate.edu/ which is linked to your OSU credentials. In order to add a map to glidermfmc0 or gliderfmc1, one must first create a map and add it to the GeoServer.

The easiest way to add a map is to follow Pat’s Github tutorial using his Isobaths repository. One must either create the map using the GEBCO or NOAA map creation service. If using the GEBCO site, create a Grid 2D netcdf. This will produce a 15 arc second map.

It is easiest to clone the Isobath repository to your local: git clone https://github.com/mousebrains/Isobaths.git

Add the netcdf map file to this folder, and then run a command similar to this:
python gebco.isobaths.py --nc gebco_2025_channel_islands.nc --shp southern_california.shp --contour=“10,20,50,100,150,200,250,300,350,400,450,500,550,600,650,700,750,800,850,900,950,1000” --plot

Once a map is created, upload it to the GeoServer:

  1. Add the files created to gliderfs3
    1. home/server/homes/pi/verweybr/Stores/socal
    2. You may need to create the Stores directory in your home directory
  2. Create a new Stores on the GeoServer
    1. Directory of spatial files (shapefiles)
    2. Directory of shapefiles
      1. file:///home/server/homes/pi/username/Stores/socal
  3. Add a new layer for the map on the GeoServer
  4. Under the Publishing heading, select Default Style - Gliderwms:IsoBath so that the map shows up with bathymetry numbers.
  5. Login to gliderfmc0/1 and under your username in the upper right select Map Settings -> Map Layer Settings
  6. Create WMS Layer Setting
    1. https://gliderwms.ceoas.oregonstate.edu/geoserver/Gliderwms/wms?
    2. Format: image/svg

Glider Simulation

To do on bench testing, the glider must be put in simulation mode by adding a file called simul.sim that has the text on_bench or just_electronics in it. When the glider boots up, it will immediately see the simul.sim file and then go to on_bench mode.

One can either add simulated variables to the autoexec.mi file or you can create them in a mission file and then use the command loadmission *mission_name.mi* to load the variables to the glider. If you do the latter (preferred method) the loadmission simulated variables will override any simulated variables in the autoexec.mi.

For example, the file contents in the custom mission file simulated_test.mi are as follows:

# Simulated variables for bench testing of SL1267 in lab
# Initialize simulation parameters

sensor: s_battery(volts) -1

sensor: s_coulomb_relative_charge(%) 40.0

sensor: s_water_depth_avg(m) 2000.0
sensor: s_water_depth_delta(m) 1500.0
sensor: s_water_depth_wavelength(m) 10000.0

sensor: s_water_cond(S/m) 4.1 # conductivity, How salty it is

sensor: s_water_temp_surface(degc) 30.0 # temp above
sensor: s_water_temp_depth_inft(m) 50.0 # this depth (inflection top)

sensor: s_water_temp_bottom(degc) 3.0 # temp below
sensor: s_water_temp_depth_infb(m) 400.0 # this depth (inflection bottom)

# sensor: s_vehicle_temp_tc(1/sec) 0.01 # tc ==> time constant

sensor: s_wind_speed(m/s) 0.0 # how fast the wind is blowing, 3.0 ==> 5.4 knots
# sensor: s_wind_direction(rad) 0.0 # Direction wind is blowing FROM

sensor: s_water_speed(m/s) 0.00 # Current speed, 0.5 ==> 1knot
# sensor: s_water_direction(rad) 4.712 # direction current is going TO,
# toward the west

# sensor: s_water_speed_fast(m/s) -1 # in, set to -1 to disable
# sensor: s_water_speed_fast_zone_x_min(m) 0 # in
# sensor: s_water_speed_fast_zone_x_max(m) 0 # in

sensor: s_mag_var(rad) -0.089 # mag_heading = true_heading + mag_var
# Taiwan

sensor: s_ini_lat(deg) 4772.4867 # North Beach, Seattle
sensor: s_ini_lon(deg) -12239.8383 # North Beach, Seattle

sensor: s_ocean_pressure_min(volts) 0.20 # used to generate voltage for 0 pressure

To run a simulated mission, you follow the same protocol as creating any other ‘real’ mission. You can configure a project in SFMC, create your mission plan with waypoint, surface, yo, etc files.

The best way to run a simulated mission in the lab is via gliderfmc1, which is the Raspberry Pi that Pat has set up on the server rack in the SE corner of the lab. To connect to gliderfmc1, direct connect a communication cable between the gliders comm port and the USB on the pack of the Pi. Go th gliderfmc1, Configuration, System Status, and look for one of the ports to become active. Click on the terminal window, and then type in ‘whoru’ into the terminal line. The glider number should appear in the terminal, in which case you can then communicate with the glider.

You can also run a simulated mission just over Freewave, but this will not ‘connect’ to Iridium or send files to SFMC like it will on gliderfmc1..

To run a mission, load the simulated variables in the custom .mi file (ex. loadmission simulated_test.mi). Then sequence *mission_name.mi*(5) to run the mission. As with any other mission, once the glider dives, select an XML script to run so that when the glider connects with Iridium (in this case the glider thinks it is connecting with Iridium but is not actually), the glider can accept dockzr commands and get .ma files from the dockserver and send files to the dockserver from the dockserver. If you are running over freewave, you do not need a xml script.
